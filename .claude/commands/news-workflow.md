# / news-workflow
뉴스 수집기 앱에서 새 기능을 개발할 때 사용하는 워크플로우입니다.
사용법: `/news-workflow <브랜치 이름>`

## 실행 순서

### 1. 현재 상태 확인
- `git status`와 `git branch --show-current`로 현재 상태와 브랜치를 확인해 줘.
- main 브랜치가 아니라면 경고를 주고, main으로 이동할지 물어봐 줘. 커밋되지 않은 변경이 있으면 함께 알려 줘.

### 2. 새 브랜치 만들기
- `$ARGUMENTS`로 받은 이름으로 새 브랜치를 만들고 전환해 줘.
- 브랜치 이름을 입력받지 못했다면 어떤 기능을 개발할 것인지 물어보고, 영어 소문자-하이픈 형식(예: `category-edit`)으로 브랜치 이름을 제안해 줘.

### 3. 개발 시작 안내
- 브랜치 생성이 끝나면 "이제 개발을 시작하세요!"라고 안내해 줘.
- `CLAUDE.md`를 읽고 이 프로젝트의 기술 스택과 컨벤션을 다시 한번 알려 줘.

### 4. 완료 처리
- 사용자가 "완료" 또는 "done"이라고 입력하면 변경된 파일 목록을 보여 줘.
- 커밋 메시지를 자동으로 제안해 줘. 형식은 한글 `[기능]요약` + 빈 줄 + 상세설명(최대 5줄)이다.
- 사용자가 확인하면 커밋하고, main으로 전환해 병합해 줘. 푸시는 하지 않는다.

### 5. 작업 요약
- 병합이 끝나면 브랜치 이름, 커밋 내역, 변경된 파일 등 작업 내용을 요약해서 보여 줘.
